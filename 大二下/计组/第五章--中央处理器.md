# 5.1 CPU功能和组成
## 功能
指令控制
操作控制
时间控制
数据加工
中断处理
## 基本结构
CPU由运算器、cache和控制器三部分组成
### 运算器和控制器
运算器对数据加工
执行所有算术运算；所有逻辑运算，并进行逻辑测试
控制器取指令，分析指令，执行指令。还有中断处理
取出指令并指出下一条指令内存中的位置；控制数据流动方向
#### 运算器的基本结构
1. 算术逻辑单元ALU
2. 通用寄存器组R0~R3：AX、BX、CX、DX、SP(堆栈指针)等
3. 暂存寄存器DR：存从主存读来的数据
4. 累加寄存器：暂时存放ALU运算结果
5. 程序状态字寄存器PSW：保留各种状态信息(溢出、零标志、负标志、进位)
6. 移位器
7. 计数器：控制乘除运算操作步数
#### 控制器的基本结构
1. 程序计数器PC
2. 指令寄存器IR：保存正在执行指令
3. 指令译码器ID
4. 微操作信号发生器
5. 时序系统：由时钟得到
6. 存储器地址寄存器MAR
7. 存储器数据寄存器MDR

# 流水线技术与流水线处理器
## 1、五阶段
取指令IF fetch
译码ID decode
RISC处理器中，数据一定来自通用寄存器
执行EX execute
访存M memory
写回WB writeback（有可能不需要）
 
## 2、性能指标
1. **吞吐率TP** 单位时间完成任务数量
$TP=\frac{n}{T_k} \approx \frac{1}{\Delta t}$，一条指令可能包含k个阶段，一条指令需要一个机器周期，也即k个时钟周期
2. **加速比** 不使用流水线时间：使用流水线时间
$S=\frac{T_0}{T_k}=\frac{k \times \Delta t \times n}{(k+n-1)\Delta t} \approx k$
3. **效率** 设备利用率，忙碌时间占总时间比例。可以用n个任务占时空区有效面积 ：总面积

## 3、影响因素
1. **结构相关（资源冲突）**
多条指令同一时刻争用同一资源
    解决办法：
    1. 后一相关指令暂停一周期
    2. 资源重复配置：数据存储器+指令存储器
2. **数据相关（数据冲突）**
前一条指令和后一条指令共用某个存储器内数据
     解决方法：
     1. 暂停。硬件阻塞 stall（指令后加pupple）或软件nop（空指令）![[screenshot_20260728_135420_yylx.danmaku.bili.png|400]]
     2. 数据旁路
     3. 编译优化（类似把nop空指令换成后续不受影响的指令）
 3. **控制相关（控制冲突）**
改变pc值的指令发生
     解决方法：
     1. 分支预测
     2. 预取成功和不成功两个指令
     3. 加快和提前形成条件码（比如加法器提前进位）
     4. 提高转移方向准确率（针对1.的优化）

## 5、多发技术
1. 超标量技术
==不能调整指令执行顺序==
配置多个功能部件
每个时钟周期并发多条独立指令（==同一个时刻==）
2. 超流水技术
==不能调整执行顺序==
一个时钟周期内再分段，一个功能部件可能多次使用
3. 超长指令字
执行时功能部件不一样就可以并行
由编译程序挖掘出，将多条能并行的指令组成一条
# RISC处理器
三要素
1. **有限**，简单，指令集
2. CPU配备大量**通用寄存器**
3. 对指令流水线**优化**
特征
*等长*指令，32位典型长度4字节
寻址方式一般*2~3种*且简单，无寄存器间接寻址方式
只有*取数指令和存数指令*，无SS型指令
指令数目一般*少于100种*，指令格式一般少于4种
控制器多采用*硬布线*
平均所有指令执行*一个处理时钟周期*
整数寄存器不少于*32*个，浮点数寄存器不少于*16*个
*通用寄存器*资源优化
*指令流水*
*编译程序复杂*，因此软件系统开发时间长
